Notes on methodology:
- Each test launches the Master, which generates a random target in [1, 1000]
  and spawns the listed agents.
- Each agent draws Random.Next(1, 1001) in a tight loop until it hits the target.
- The Master records per-agent elapsed time using Stopwatch from the moment
  TARGET is sent until the GUESS reply is read.
- "Attempts" in agent console output is the number of draws it took.
  On a uniform RNG the expected value is 1000 per agent.

----------------------------------------------------------------
Conclusions
----------------------------------------------------------------
1. Named Pipes with PipeDirection.InOut and maxNumberOfServerInstances
   give a clean 1:1 duplex channel per agent while letting all of them
   share a single pipe NAME, which matches the assignment's requirement
   that "Both Agents connect to the same Named Pipe."

2. async/await on WaitForConnectionAsync / ReadLineAsync / WriteLineAsync
   means the Master never blocks a thread. Adding more agents costs
   roughly nothing on the Master side until the wait-for-winner moment.

3. Winner detection is correct under race conditions: a lock around the
   winner field plus a single CancellationToken ensures only the first
   correct GUESS wins, even when two agents finish microseconds apart.

4. ProcessorAffinity is intentionally guarded behind OperatingSystem.IsWindows()
   because the .NET API throws PlatformNotSupportedException on macOS/Linux.
   The same binary, run on Windows, will print "[CpuPinning] Pinned to core N".
